## 二、智能精修引擎

### 2.1 能力边界

引擎只用确定性本地算法：亮度/直方图统计、R/B 与 G 通道偏差、饱和度、拉普拉斯残差、高频方差、平坦区噪声估计、已有 YuNet 人脸结果、已有手动蒙版/背景/美肤参数。**没有生成式模型参与**，界面文案统一为「智能精修建议 / 本地照片分析」。

每项指标都有 `status`：

- `ok`：有真实数据
- `lowConfidence`：算法只能给出参考值（局部对比度、清晰度、噪点）
- `noData`：输入缺失（例如未检测到人脸）
- `unsupported`：能力未启用
- `failed`：计算失败

无数据时 `value` 为 `null`，界面显示明确原因，不会返回「正常」占位值。皮肤指标能力标记为 `beautyAnalysis: false`（第三轮没有可商用皮肤权重），因此只给保守美肤模板，并在建议原因中注明「不声称检测到具体皮肤问题」。

### 2.2 分析指标

| key | 名称 | 数据来源 | 置信度 |
| --- | --- | --- | --- |
| `exposure.mean` | 平均亮度 | 亮度均值 + 中位数 | ok |
| `exposure.contrast` | 明暗对比 | 亮度标准差、P5/P95 | 标准差 < 0.06 时低置信 |
| `exposure.clipHighlights` | 高光裁切 | ≥ 98% 亮度像素占比 | ok |
| `exposure.clipShadows` | 暗部压死 | ≤ 2% 亮度像素占比 | ok |
| `color.temperatureBias` | 白平衡 R/B 偏差 | 三通道均值 | ok |
| `color.saturation` | 平均饱和度 | HSV 饱和度均值 | ok |
| `detail.localContrast` | 局部对比度 | 拉普拉斯残差 | lowConfidence |
| `detail.sharpness` | 清晰度指标 | 高频方差 | lowConfidence |
| `detail.noise` | 噪点风险 | 平坦区域残差 | lowConfidence |
| `portrait.faces` | 人脸数量 | 现有 YuNet 结果 | 无脸时 noData |
| `portrait.manualMask` | 手动人物蒙版 | 现有蒙版笔触 | ok |
| `portrait.beautyParams` | 已有美肤参数 | 当前参数 | ok |
| `portrait.background` | 背景分离 | 当前背景参数 | ok |

分析在长边不超过 720px 的样本上运行（`SAMPLE_MAX_EDGE = 720`），原图 hash 仍在全图上计算。

### 2.3 建议规则（确定性）

| 触发条件 | 建议参数 | 建议值（未乘模式系数） | 置信度 |
| --- | --- | --- | --- |
| 平均亮度偏离 0.46 | 曝光 | `(0.46 - mean) × 90`，限 ±25 | 0.80 |
| 高光裁切 > 2% | 高光 | `-裁切% × 9`，限 -38..-4 | 0.78 |
| 暗部压死 > 3.5% | 阴影 | `压死% × 7`，限 4..36 | 0.75 |
| P99 > 0.97 且高光裁切 > 0.5% | 白色色阶 | -8，限 -20..-3 | 0.62 |
| 标准差 < 0.13 | 对比度 | `(0.14 - std) × 260`，限 4..22 | 0.78 |
| 标准差 > 0.27 | 对比度 | `-(std - 0.24) × 150`，限 -20..-3 | 0.70 |
| R/B 偏差 > 0.035 | 色温 | `偏差 × 240`，限 ±20 | 0.65 |
| 绿/品红偏差 > 0.025 | 色调 | `偏差 × 220`，限 ±12 | 0.60 |
| 饱和度 < 0.17 | 自然饱和度 | `(0.18 - sat) × 150`，限 4..18 | 0.70 |
| 饱和度 > 0.48 | 饱和度 | `-(sat - 0.44) × 70`，限 -20..-3 | 0.66 |
| 清晰度 < 0.035 | 锐化 | `(0.045 - sharp) × 420`，限 5..22 | 0.55 |
| 局部对比度 < 0.018 | 清晰度 | `(0.022 - lc) × 520`，限 3..16 | 0.55 |
| 有人脸且未设置美肤 | 人脸磨皮/纹理/肤色/祛痘/黑眼圈/法令纹 | 保守模板 6 项，上限 35 | 0.55 |
| 噪点估计 > 0.05 | 仅警告 | — | — |

所有建议值最终 `clamp(最小值, 最大值)` 并取整；与当前值差值 < 0.5 时不生成建议，避免无意义条目。

### 2.4 四种模式

模式只调整系数，不改变判断条件：

| 模式 | 曝光/色彩系数 | 细节系数 | 美肤系数 |
| --- | --- | --- | --- |
| 自然（默认） | 0.55 | 0.50 | 0.45 |
| 轻度 | 0.78 | 0.80 | 0.70 |
| 标准 | 1.00 | 1.00 | 1.00 |
| 强化 | 1.22 | 1.12 | 1.15 |

### 2.5 建议合并

`apply_suggestions` 只处理被用户勾选的建议，逐字段合并：

- 普通参数：直接写入建议值，不触碰未选字段；
- 人脸美肤：`max(当前值, 建议值)`，不会抹掉用户更强的设置；
- 当前参数没有人脸条目时，按实际检测到的人脸创建条目；
- 结束后统一 `clamped()`，保证结果合法。

应用后写入的是普通 `EditParams`，用户可以继续手动调节，也可以撤销（前端 `applyExternalParams` 走正常历史栈）。

### 2.6 分析缓存

`AnalysisCache` 按图片路径保存最近一次结果，命中键包含：

- 原图内容 hash（SHA-256）
- 人脸签名
- 参数签名
- 模式
- 算法版本 `local-analysis-1` / 结果版本 `1`

命中时返回 `cached = true`；输入或版本变化时重算并返回 `stale = true`，提示旧结果可能过期。分析在 `spawn_blocking` 中运行，不阻塞 UI。

## 三、预设引擎

### 3.1 数据结构

`RetouchPreset { id, name, category, description, version, source, params, suitableFor, avoid, preview }`。

`PresetParams` 只允许调色与美肤模板：

- 14 个标量：曝光/对比/高光/阴影/白色/黑色/色温/色调/饱和度/自然饱和度/清晰度/锐化/颗粒/暗角
- HSL 8 通道
- 曲线（RGB/红/绿/蓝）
- LUT 名称 + 强度（不存绝对路径）
- 美肤模板 `BTreeMap<String, f32>`

**类型层面排除**：原图路径、缓存、原图 hash、项目 ID、人脸/人物 UUID、手动蒙版笔触、背景图片路径、网格变形记录、已检测人脸坐标。序列化白名单由测试 `builtin_presets_serialize_only_whitelisted_fields` 保护。

### 3.2 强度混合（0–100%）

- 标量：`当前 + (目标 - 当前) × t`
- HSL：逐分量插值
- 曲线：先规范化（排序、去重、补齐 0/1 端点），在两条曲线的并集 x 上逐点线性插值，最多 32 点
- LUT：仅在目标照片已有同名 LUT 时混合强度；名称不同或无 LUT 时跳过并给出警告，绝不写入路径
- 美肤：逐字段插值，只作用于目标照片自己的人脸；无人脸时跳过并警告
- 0% 必须与不应用完全一致；布尔、UUID、蒙版、锚点不参与插值

### 3.3 预览

- 预设库缩略图：对当前照片的缩略图（默认 240px）逐个 100% 渲染，走正式 `pipeline::render`，不是占位图
- 单预设实时预览：360px、150ms 防抖，只在小尺寸上重算
- 悬停不触发全尺寸运算；切换预设才请求新预览

### 3.4 自定义预设

- 保存/覆盖/重命名/复制/删除；内置预设禁止覆盖与删除
- 导入：文件内容强制作为新自定义预设写入，生成新 ID
- 导出：写入标准 JSON 预设文件
- 持久化：`~/.lumi-retouch/presets.json`，只存自定义预设；临时文件 + rename 原子写
- 内置预设 14 个，见 `ROUND6_PRESET_CATALOG.md`

## 四、批量引擎

### 4.1 多选与复制

- 单选、多选、全选、取消全选、反选、按名称排序、按格式筛选、已选数量
- 参数复制分组：基础光影、白平衡、色彩、HSL、曲线、LUT、细节、美肤模板
- 对象级数据（人脸美肤、塑形/五官、手动人物蒙版、身材、背景、修复点）默认排除，并在界面逐条说明原因
- LUT 名称不一致时保留目标 LUT 并警告
- 美肤模板取源照片所有人脸字段最大值，只写入目标照片自己的人脸

### 4.2 批量套预设

选多张 → 选预设 → 选强度 → 确认 → 逐张用各自参数调用 `apply_preset`，每张保留独立参数历史，不合并成不可分离状态。

### 4.3 批量导出

- 格式 JPEG/PNG/WebP、质量、原图尺寸
- 命名规则支持 `{name}` / `{index}` / `{format}`，起始编号可设
- 冲突策略：跳过（默认）/ 重命名 / 明确勾选确认后覆盖
- 走 `pipeline::render_with_progress` 全尺寸渲染，不使用缩略图
- 原子写：同目录临时文件 + rename；拒绝覆盖源文件
- 文件名中的控制字符与路径分隔符替换为 `-`

### 4.4 队列架构

- 单个后台工作线程，逐张处理；每张完整渲染并写盘后才进入下一张
- 独立 `ImageCache::with_budget(1, 640MB)`，任意时刻最多保留一张全尺寸图
- 任务状态：Pending / Running / Completed / Failed / Cancelled / Skipped
- 每个任务记录 Job UUID、路径、编号、阶段、进度、输出路径、错误、起止时间、尺寸、字节数
- 暂停在任务之间生效；取消当前通过 `CancelToken` 在阶段边界中止；取消全部同时中止当前渲染并把未开始任务标为 Cancelled
- 单张失败隔离，继续处理后续任务
- 进度事件 `lumi://batch-progress` 120ms 节流；ETA 只用已完成任务的实际耗时样本，样本不足时为 `null`
- 部分成功可识别（Completed 与 Failed 分开计数）；失败任务可单独重置重试
- 重启后不会把部分导出标成全部完成（状态只存在于本次进程，快照按真实状态恢复）

## 六、项目与缓存

- 项目格式仍为 v3（第五轮版本），本轮不修改 `ProjectDoc` 结构；预设库不写入项目文件
- 渲染缓存键仍包含原图 hash、尺寸、完整参数、人脸/蒙版/身材/背景版本、渲染算法版本；预设混合结果作为普通参数参与缓存

## 七、安全边界对照

| 边界 | 实现 |
| --- | --- |
| 不上传照片 | 全部本地算法，无网络请求 |
| 不用未授权模型 | 未新增模型；皮肤能力标记为不可用 |
| 不擅自改身份特征 | 建议只含调色与美肤模板，不含塑形 |
| 不无确认覆盖源照片 | `write_atomic` 拒绝 destination == source |
| 不批量覆盖参数而无撤销入口 | 复制/应用走 `applyExternalParams`，进入历史栈 |
| 不跨图盲目套人脸参数 | 分组层排除 faces/reshape/mask/body/background |
| 不把蒙版与锚点当普通调色参数 | `COPY_GROUPS` 不含这些字段 |
| 建议不静默覆盖全部参数 | 只合并勾选项，逐字段写入 |
| 不显示虚假模型状态 | `beautyAnalysis: false`，UI 显示「不支持」 |
| 取消后不写未完成文件 | 临时文件 + rename，失败清理 |

## 九、已知限制

1. 皮肤指标未启用（无可商用权重），人像建议为保守模板，置信度固定 0.55。
2. 清晰度/噪点指标为启发式估计，已标为低置信度。
3. 批量暂停只在任务之间生效，正在渲染的单张会先完成或手动取消。
4. 覆盖冲突必须由用户勾选确认，默认永不覆盖。
5. 预设缩略图依赖当前照片，首次生成需要逐张渲染，照片很多时会有一小段等待。
