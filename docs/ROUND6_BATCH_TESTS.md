# 第六轮批量与性能实测

测试环境：macOS 27.2.1，Apple M4，16 GB 内存。
数据来源：`src-tauri/src/commands/batch.rs` 单元测试与 `round6_performance_baseline`（release 构建）。

## 一、批量队列测试矩阵

| 场景 | 输入 | 结果 |
| --- | --- | --- |
| 混合批次（真实导出） | 3 张：120×80 PNG、64×48 PNG、1 个伪装成 .png 的文本文件 | 完成 2、失败 1；输出 2 个文件；源图字节不变；无 `.lumi-tmp-*` 残留 |
| 取消全部 | 2 张 200×140 PNG，运行前触发取消 | Cancelled 2、完成 0；输出目录为空；失败原因为「批次已取消，未写入文件」 |
| 部分成功后重试 | 1 张 96×72 PNG + 1 个坏文件，修复坏文件后仅重试失败项 | 首次完成 1 / 失败 1，输出 1 个；重试后完成 2 / 失败 0，输出 2 个，已完成任务未被重置 |
| 同名冲突（默认跳过） | 1 张 64×48 PNG，输出目录已存在 `photo-out.jpg`（内容 `keep-me`） | Skipped 1、完成 0；已有文件内容保持 `keep-me` |
| 混合尺寸与格式 | 10 张：96×64、72×90、120×80 交替使用 PNG 与 JPEG 输入，输出目录不存在 | 完成 10、失败 0；自动创建输出目录；10 个 `.jpg` 文件均可正常解码 |
| 单张 vs 批量一致性 | 1 张 200×150 PNG，预设「暖调肤色」65%，JPEG 90 | 批量导出与单张导出文件逐字节一致 |
| 预设强度渲染等价 | 1 张 64×48 PNG | 0% 渲染与未应用预设完全相等；100% 与基准像素不同 |
| 原子导出 | 1 张 96×64 PNG | 输出尺寸等于原图；源文件不变；无临时文件 |

说明：单元测试使用小尺寸图片以保持测试速度；真实尺寸性能见下一节。坏图使用非图片字节模拟解码失败，不是伪造的错误分支。

## 二、性能实测（release 构建）

参数：内置预设「自然通透」100% 再叠加锐化 18、清晰度 12；批量导出 JPEG 质量 90。

| 项目 | 实测 |
| --- | --- |
| 单张 1600×1200（PNG 解码 + 完整渲染 + PNG 编码） | 0.056 s |
| 单张 3000×4000（同上） | 0.368 s |
| 批量 10 张 1600×1200 | 1.07 s 总计，0.107 s/张，完成 10 / 失败 0 |
| 批量 50 张 1600×1200 | 5.69 s 总计，0.114 s/张，完成 50 / 失败 0 |
| 取消响应（10 张 3000×4000 批次运行中触发取消） | 0.137 s；完成 0、取消 10、无部分写盘 |
| 峰值常驻内存（整个测试进程，200 ms 采样） | 约 791,840 KB（≈ 773 MB） |

内存说明：该数值是测试进程在包含 3000×4000 图片、预览与多个缓冲阶段时的整体峰值，不是单任务占用；批量线程自身使用独立 1 张容量的图片缓存（预算 640 MB）。

未执行项：为避免测试耗时过长，未运行 50 张 3000×4000 的完整批次；未测量单独进程的堆峰值（受工具限制）。以上数字均为本次真实运行输出，没有估算或填充。

## 三、复现命令

```bash
# 常规测试
cd src-tauri && cargo test

# 性能基线（约 1 分钟，需 release 编译）
cd src-tauri && cargo test --release --lib round6_performance -- --ignored --nocapture
```
