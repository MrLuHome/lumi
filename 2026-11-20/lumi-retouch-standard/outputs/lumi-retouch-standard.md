## 0. 文档性质核查（先读这一节）

### 0.1 核查结论

**该文档不是「人像修图作业标准」，而是「专业 AI 人像修图软件的产品与技术开发总方案」。**

原文第 1 页自述：

> 「我建议把这个项目按照真正商业级桌面修图软件的标准来做，而不是做一个简单的 AI 美颜 Demo。」
> 「下面这份流程可以直接作为整个项目的开发总方案，也可以交给 Codex、Claude Code 或其他 AI 编程工具作为项目执行规范。」

因此原文的主线是：技术选型 → 工程搭建 → 图像引擎 → AI 模型 → 各功能引擎 → 界面 → 性能 → 导出 → 测试与商业化。它描述的是**软件要做什么、怎么实现、如何验收开发成果**，而不是**修图师拿到一张人像后应如何修、修到什么程度算合格**。

## 1. 产品定位与适用范围

### 1.1 一句话定位

开发一款类似「像素蛋糕」的专业人像精修软件：支持 macOS 与 Windows，AI 模型全部本地运行，照片不上传云端，断网也能完成修图。

原文自评标准：

> 「我建议把这个项目按照真正商业级桌面修图软件的标准来做，而不是做一个简单的 AI 美颜 Demo。」

### 1.2 目标平台与运行约束

| 维度 | 原文要求 |
| --- | --- |
| 操作系统 | macOS、Windows |
| 运行方式 | 桌面应用（Tauri 2） |
| AI 推理 | 全部本地运行，ONNX Runtime |
| 网络 | 断网可用；照片默认不上传；运行时不得请求云端推理接口 |
| 模型获取 | 安装时下载；缺失时提示用户安装模型包，「不要偷偷联网下载」 |
| 在线能力 | 自动更新、在线下载模型都必须是**可选**功能 |
| 画质 | 不以低分辨率预览代替最终成片；导出必须在原始分辨率重算 |

### 1.3 目标能力清单（原文 13 项）

1. 专业照片导入、管理和浏览
2. AI 自动识别人脸及多个面部区域
3. 自然磨皮、祛痘、祛斑
4. 美白、肤色均匀、肤色保护
5. 瘦脸、大眼、鼻型、嘴型调整
6. 身材调整
7. 人像分割、背景虚化及替换
8. 专业色彩调整和滤镜预设
9. AI 一键精修
10. 批量同步修图
11. RAW 图片处理
12. 高分辨率导出
13. 完整的撤销、重做和非破坏性编辑

### 1.4 产品原则（原文表 1）

| 原则 | 具体要求 |
| --- | --- |
| 本地优先 | 不依赖云端 AI API |
| 隐私 | 默认不上传照片，不联网传输图片 |
| 高画质 | 不以低分辨率预览代替最终成片 |
| 自然 | 保留皮肤纹理和人物辨识度 |
| 流畅 | 调整参数时尽量实时响应 |
| 可扩展 | 每个 AI 引擎独立开发 |
| 可维护 | 模型、算法、UI 分层管理 |

### 1.5 适用对象

| 对象 | 用途 |
| --- | --- |
| 产品/项目负责人 | 按第 8 章阶段表推进，按第 7 章验收 |

## 2. 总体技术架构

### 2.1 分层架构（原文）

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 桌面 UI | React + TypeScript | 桌面 UI、画布、参数面板、交互 |
| 容器层 | Tauri 2 | 桌面窗口、文件系统、原生接口 |
| AI 推理层 | ONNX Runtime | 人脸识别、分割、检测 |
| 图像处理层 | Rust + OpenCV | 美肤、修复、色彩、变形 |
| GPU 渲染层 | Mac Metal / Windows DirectML 或 CUDA / WebGPU | GPU 加速与实时预览 |
| 存储层 | 本地文件 + SQLite | 原始照片、AI 蒙版、编辑参数、导出结果 |

### 2.2 技术选型明细（原文表 2）

| 技术 | 负责工作 |
| --- | --- |
| Tauri 2 | macOS、Windows 桌面应用 |
| React | 用户界面 |
| TypeScript | 前端业务逻辑 |
| Rust | 图像处理调度、文件和任务管理 |
| ONNX Runtime | 本地 AI 模型推理 |
| MediaPipe | 人脸关键点 |
| OpenCV | 图像处理、局部修复 |
| Metal | Apple GPU 加速 |
| DirectML / CUDA | Windows GPU 加速 |
| WebGPU | 实时预览和画布处理 |
| SQLite | 本地项目、历史记录、预设 |

### 2.3 架构约束

- GPU 后端必须做设备检测与兼容性适配；「不要假设所有电脑都能使用相同的推理后端」。
- 图像底层、非破坏性编辑、模型管理必须提前设计，「开发顺序不要颠倒」。

### 2.4 GPU 加速平台（原文 14.1）

| 平台 | 原文要求 |
| --- | --- |
| macOS | Apple Silicon GPU、Metal、Core Image 或自定义 GPU 渲染 |
| Windows | CUDA（兼容的 NVIDIA 显卡）、DirectML、适配不同设备的推理后端 |

## 4. 分环节标准（按引擎）

### 4.1 图片输入与数据基础

#### 4.1.1 解码格式支持（原文表 3）

| 格式 | 支持目标 |
| --- | --- |
| JPEG | 完整支持 |
| PNG | 完整支持 |
| WebP | 完整支持 |
| TIFF | 后续完善 |
| RAW | 后续专业支持 |

RAW 要求：针对相机格式接入 LibRaw 或其他合适解码方案，并处理白平衡、色彩配置文件等问题。

#### 4.1.2 单张图片必须保留的数据项（原文）

1. 原始宽度和高度
2. 色彩空间
3. 位深
4. EXIF 信息
5. 原始图像数据
6. 预览图像
7. 缩略图
8. 编辑参数

约束：不要把所有照片一开始都完整加载进内存。

#### 4.1.3 多分辨率策略（原文表 4，示例为 6000 × 4000 照片）

| 图片数据 | 用途 |
| --- | --- |
| 600 × 400 | 快速缩略图 |
| 1500 × 1000 | 普通预览 |
| 3000 × 2000 | 高质量预览 |
| 6000 × 4000 | 最终导出 |

规则：预览使用较小图像；最终导出必须重新在原始分辨率上处理。

### 4.2 非破坏性编辑

原文要求：只保存参数，不直接修改原图。原文示例参数对象（**示例，非默认值**）：

```json
{
  "beauty": {
    "smooth": 35,
    "blemish": 50,
    "skin_tone": 20
  },
  "color": {
    "exposure": 0.3,
    "contrast": 10,
    "temperature": 5
  }
}
```

配套规则：

- 每次修改只重新渲染受影响的处理节点。
- 所有处理都要可逆；用户可随时关闭磨皮、恢复五官、调整肤色，不覆盖原图。
- 历史记录按「原始照片 → AI 自动分析 → 磨皮调整 → 祛痘处理 → 五官调整 → 色彩调整 → 最终效果」保存状态，可随时回到之前状态。

### 4.3 人脸分析与蒙版

#### 4.3.1 人脸检测输出

每张脸输出：人脸位置、人脸边界框、置信度、人脸尺寸。支持一张照片多人物。

#### 4.3.2 五官关键点（原文 8 类）

脸部轮廓、左右眼、眼角、眉毛、鼻梁、鼻翼、嘴唇、下巴。

要求：

- 坐标映射回原始照片尺寸；
- 必须测试侧脸、遮挡、眼镜、低光照和多人场景，「避免只在正脸上有效」。

#### 4.3.3 区域蒙版清单（原文 8 个）

`face_mask`、`skin_mask`、`left_eye_mask`、`right_eye_mask`、`eyebrow_mask`、`nose_mask`、`lip_mask`、`hair_mask`。

蒙版质量要求：不能只有简单黑白二值图，须支持灰度边缘、羽化和置信度。

#### 4.3.4 多人脸独立参数（原文示例，非标准值）

| 人物 | 磨皮 | 瘦脸 | 肤色 |
| --- | --- | --- | --- |
| 人物 A | 35 | 10 | 20 |
| 人物 B | 20 | 0 | 10 |

规则：每个人都必须有独立的修图参数。

### 4.4 美肤引擎

原文定位：首版最重要引擎，「应该投入最多精力」，因为用户一眼就能看出修图是否自然。

#### 4.4.1 磨皮

**算法要求（原文明确禁止简单高斯模糊）**：采用「边缘保护滤波 + 频率分离 + 纹理保护 + 蒙版融合」。

处理步骤（原文 9 步）：

| 序号 | 步骤 |
| --- | --- |
| 1 | 读取原图 |
| 2 | 提取皮肤区域 |
| 3 | 将图像分解成低频和高频信息 |
| 4 | 对低频皮肤色彩进行平滑 |
| 5 | 保留高频毛孔与细节 |
| 6 | 根据磨皮强度混合处理结果 |
| 7 | 使用皮肤蒙版融合 |
| 8 | 保护眼睛、眉毛、嘴唇和头发 |
| 9 | 输出处理结果 |

参数（原文表 7，全部仅给 0–100 范围）：

| 参数 | 范围 | 默认值 | 单位 | 推荐区间 |
| --- | --- | --- | --- | --- |
| 磨皮强度 | 0–100 | 原文未明确 | 原文未明确（无量纲） | 原文未明确 |
| 细节保留 | 0–100 | 原文未明确 | 原文未明确 | 原文未明确 |
| 纹理保护 | 0–100 | 原文未明确 | 原文未明确 | 原文未明确 |
| 边缘保护 | 0–100 | 原文未明确 | 原文未明确 | 原文未明确 |
| 局部平滑 | 0–100 | 原文未明确 | 原文未明确 | 原文未明确 |

> 「自然」在原文中无任何量化定义（无纹理保留率、无频段能量比、无客观指标阈值），见 C-06。

#### 4.4.2 祛痘祛斑

原文流程 6 步：

| 序号 | 步骤 |
| --- | --- |
| 1 | 痘痘检测 |
| 2 | 瑕疵区域定位 |
| 3 | 局部内容修复 |
| 4 | 纹理重建 |
| 5 | 颜色匹配 |

#### 4.4.3 美白与肤色均匀

必须遵守：不能直接给整张脸增加亮度。

处理步骤（原文 6 步）：

| 序号 | 步骤 |
| --- | --- |
| 1 | 提取皮肤区域 |
| 2 | 识别肤色 |

### 6.4 第 21 章五条开发原则（原文）

1. **不要把 AI 模型和修图算法混为一谈。** 人脸识别负责告诉你脸在哪里，皮肤分割负责告诉你哪里是皮肤，真正让照片变漂亮的是后续图像算法和参数设计。
2. **不要过度依赖生成式 AI。** 专业人像修图必须尽量保留人物真实五官、皮肤纹理和身份特征；GFPGAN 这类生成式修复应作为可选功能，而不是默认处理。
3. **所有处理都要可逆。** 用户可以随时关闭磨皮、恢复五官、调整肤色，不要覆盖原图。
4. **本地运行必须真正做到离线。** 安装时下载模型，运行时不请求云端推理接口；断网后 AI 分析、修图、导出仍可用；自动更新和在线下载模型都必须是可选功能。
5. **必须从第一天考虑不同硬件。** Mac Apple Silicon、Intel Mac、Windows NVIDIA 和普通 Windows 电脑都要建立独立的兼容性测试。

## 10. 矛盾、歧义、空缺清单

> 分四级：A 性质类（影响文档能否作为修图标准）、B 结构/编号类、C 参数缺失类、D 格式/附件类。

### A. 性质类

**C-01 文档性质与「人像修图标准」不符（最高优先级）**
原文是软件开发总方案/技术蓝图，不是修图作业 SOP。全文没有：成片风格定位、单张照片修图步骤规范、修图前后对比基准、修图师操作顺序（如先液化还是先磨皮）、修图合格样片库。
→ 本稿按原文内容整理为「产品与开发标准」，未代拟修图标准。

**C-02 双轨阶段编号，互相冲突**
正文标注「第一至第十四阶段」共 14 个（3–16 章），第 17 章验收表却列 15 个阶段（01–15）。差异：表中把「图片处理引擎」拆为「02 图片管理 + 03 图像引擎」，把「人脸分析」拆为「05 人脸分析 + 06 皮肤分割」，同时**省略了「第十一阶段 桌面软件界面」**。原文未说明以哪套编号为准。

### B. 结构/歧义类

**C-03 「图层合成」节点缺前置定义**
原文 4.5 节管线第 9 节点为「图层合成」，但全文没有图层系统的数据结构、图层类型、混合模式或蒙版层级定义。

**C-04 面板能力与正文引擎不对应**
13 章界面分组含「身体调整：瘦身/肩部/腰部/腿部」，第 8 章只写五官与脸型，无身体变形算法、关键点、参数或验收。V1.5 也列「身材调整」，但无实现规格。

**C-05 「风格预设 / 修图预设」无定义**
面板与版本规划多次出现「风格预设」，全文未定义预设包含哪些参数、如何存储、如何套用、如何与多人脸匹配。

**C-06 「自然」被反复引用但从未量化**
产品原则、磨皮、一键精修、验收均要求「自然」，但无纹理保留率、无频段能量比、无人工评分量表、无客观指标阈值。

**C-07 RAW 能力与测试范围时间不一致**
4.1 将 RAW 定为「后续专业支持」，V1.0 不含 RAW；但 16 章测试照片类型包含「高分辨率 RAW 转换图片」。此处可解释为「RAW 转换后的图片」，但原文未明确区分 RAW 解码与 RAW 转换图，存在歧义。

**C-08 GFPGAN 的定位存在张力**
5.1 将 GFPGAN 列为 P2「人脸修复增强」，21 章要求「不要过度依赖生成式 AI，GFPGAN 这种生成式修复可以作为可选功能，而不是默认处理」。两处可协调（P2 + 默认关闭），但原文**未明确写出「默认关闭」**，需产品侧确认。

### C. 参数缺失类（均标注「原文未明确」）

**C-09 磨皮 5 参数只有 0–100 范围**
无默认值、无单位（有无量纲未说明）、无推荐区间、无参数间耦合关系、无「过度磨皮」判定阈值。

**C-10 祛痘祛斑无任何数值**
无痘痘检测置信度阈值、最小/最大瑕疵面积、修复半径、纹理重建强度、颜色匹配容差。

**C-11 美白/肤色 6 项功能无参数**
自然美白、肤色均匀、去黄、红润、局部提亮、暗沉改善均只有功能名；无范围、无目标值（如 Lab/ΔE）、无肤色保护容差。

**C-12 五官 8 项功能无强度范围**
瘦脸、下巴、大眼、眼距、瘦鼻、鼻梁、嘴型、额头均无 0–100 或百分比范围，也无「最大变形量」上限。

**C-13 背景处理无参数**
无虚化半径/强度、无景深模拟参数、无边缘羽化像素、无 alpha matte 精度要求、无色溢修复容差。

**C-14 色彩引擎无任何数值**
曝光、对比度、高光、阴影、白/黑色阶、色温、色调、饱和度、自然饱和度、HSL、曲线均无单位与范围；未指定内部工作色彩空间与位深（仅提「浮点处理」「ICC」「导出可选 sRGB / Display P3」）。

**C-15 导出无任何数值**
JPEG 质量值、PNG 压缩级别、TIFF 位深、dpi、输出尺寸上限、批量命名规则、EXIF 保留项白名单，原文均未明确。

**C-16 锐化、颗粒、输出锐化完全缺失**
全文未出现「锐化」「颗粒」「噪点添加」「输出锐化」；仅有「纹理保护/保留皮肤纹理」。请求中的「质感与颗粒」「锐化与输出」两个环节在原文无对应内容。

**C-17 性能无量化指标**
「实时响应」「不卡顿」「流畅」无毫秒/FPS 目标；无 GPU 显存上限、无单图处理时间上限、无批量吞吐目标。

**C-18 所有验收均无通过阈值**
人脸检测「不漏」、磨皮「自然」、祛痘「无明显痕迹」、瘦脸「不扭曲」、肤色「不明显偏色」均为定性描述；无 IoU、无 ΔE、无人工盲评通过率、无缺陷率上限。
