审查基线：`e55eeb1`（第二轮交付）。审查方式：逐文件阅读 + 实际运行测试 + 打包应用启动，不采信报告结论。

## 1. 第二轮实际可用性核对

| 检查项 | 结论 | 证据与问题 |
| --- | --- | --- |
| 人脸检测是否真跑 | 是 | [face.rs](../src-tauri/src/ai/face.rs) 用 tract 加载 YuNet，SHA256 校验后推理；`cargo test --test face_detection` 4 项通过（单人 1、四人 4、无人脸 0、暗光 1） |
| 关键点是否准确 | 部分 | 只有 YuNet 的 5 点（双眼中心、鼻尖、左右嘴角），没有眉毛、脸缘、下巴轮廓；检测把预览图直接拉伸到 640×640，非方图会有比例畸变，关键点位置误差被放大 |
| 管线是否支持蒙版 | **否** | [pipeline.rs](../src-tauri/src/image_engine/pipeline.rs) 只接受 `EditParams`，没有任何蒙版参数；`MaskLayer` 仅存在于项目文件结构，渲染从未使用 |
| 磨皮是否真实 | **否（本轮必须替换）** | [detail.rs](../src-tauri/src/image_engine/operations/detail.rs) 的 `smooth_skin` 对全图做高斯模糊 + 亮度差混合，注释明确写“不含人脸检测，因此全图都会参与”。眼睛、嘴唇、头发、背景一起被抹平，属于“整脸模糊冒充磨皮” |
| 非破坏状态是否可靠 | 是 | 按图独立 `EditParams` 快照 + 100 步历史，600ms 合并；项目 JSON 只存参数与路径，不存预览图；`engine.rs` 与前端 37 项测试覆盖往返 |
| 原图与预览是否分离 | 是 | `CachedImage.full/preview/thumb` 三份缓冲；预览 1800px、高清 3200px、导出走 `full`；`export::write` 拒绝写回原路径并原子改名 |
| 后端是否异步 | 是 | 所有命令 `spawn_blocking`；`RenderRegistry` + `AtomicBool` 取消旧任务，阶段边界与逐像素检查 |
| ONNX 推理接入 | 是（有限） | 使用 tract-onnx 0.23 纯 Rust CPU，未接 ONNX Runtime，无 GPU 路径；仅检测模型，无分割模型 |
| 导出是否原尺寸 | 是 | `export_image` 用 `cached.full` 全尺寸渲染；引擎测试验证 3360×4480 输出尺寸与拒绝覆盖原图 |
| 多人脸独立 ID | **否** | 检测后按 x 排序赋 `id = index`；再次检测时若顺序/阈值变化会错配，且没有任何按脸参数 |
| 撤销重做处理复杂参数 | 是 | 深拷贝 `EditParams`（含 HSL/曲线/LUT）入栈；但蒙版笔触、按脸参数尚不存在，无法验证 |

## 2. 本轮必须修复的阻塞问题

### P0-1 管线没有蒙版通道

新增统一的 `FaceFrame`（归一化人脸几何 + 蒙版）并让 `pipeline::render` 接受可选人脸上下文；蒙版按工作分辨率实时生成，预览/高清/导出共用同一算法。没有检测结果时不得假装磨皮生效，应明确提示。

### P0-2 全图磨皮必须下线

用“皮肤蒙版 + 边缘保护低频平滑 + 高频纹理回注 + 多尺度融合”替代全局高斯；眼睛、眉毛、嘴唇、头发、鼻孔、背景由蒙版排除，并按关键点做几何保护。

### P0-3 按脸参数与稳定 ID

后端维护每张照片的人脸结果缓存与 ID 跟踪：以 IoU 匹配上一轮结果，匹配不上才分配新 ID；前端按 `faceId` 保存独立参数，检测顺序变化不会错配。

### P0-4 渲染拿不到人脸结果

第二轮检测结果只回传前端，渲染管线无法使用。本轮在命令层增加人脸结果仓库，渲染/导出/分析命令统一读取；滑块变化不重跑检测。

### P0-5 分割权重授权

候选与结论：

| 候选 | 权重许可 | 商用结论 |
| --- | --- | --- |
| BiSeNet Face Parsing（zllrunning/face-parsing.PyTorch） | 权重训练于 CelebAMask-HQ，数据集仅限非商业研究 | **不可商用，不打包** |
| CelebAMask-HQ 系衍生 ONNX | 同上，仓库代码许可不能推断权重许可 | **不可商用，不打包** |
| InsightFace 解析/分割权重 | 多数模型仅限非商业研究 | **不可商用，不打包** |
| MediaPipe Face Mesh | Apache-2.0 | 许可允许，但需 tflite→ONNX 转换且 tract 兼容性未验证，本轮无可靠离线产物 |
| MODNet 等抠图模型 | 输出人像前景，不输出皮肤/五官分区 | 不满足皮肤区域分割需求 |

**结论（阻塞项）**：本轮没有可确认商用许可的皮肤分割 ONNX 权重，因此不打包任何分割权重。皮肤区域采用可解释、可测试的替代方案：

1. 由 YuNet 5 关键点推导脸部坐标系（双眼连线为水平轴），生成额头、双颊、鼻部、下巴、颈部候选区域；
2. 用双眼、鼻翼、嘴缝几何挖除眼睛、眉毛、鼻孔、嘴唇，头发/衣服/背景由脸缘椭圆衰减排除；
3. 叠加 YCbCr 肤色似然，低置信度区域自动降权；
4. 蒙版做距离羽化，边缘无硬边；
5. 保留 `ai_engine/skin_segmentation` 的模型加载接口与许可证闸门：只有登记为允许商用且 SHA256 匹配的权重才会被加载，否则明确报“未授权模型已拒绝”。

该方案不是模型推理，报告中会如实标注为 `landmark-geometry`，不冒充 AI 分割。

## 3. 其他问题（本轮处理或明确记录）

1. 关键点不含眉毛与脸缘：几何蒙版用眼睛上方固定比例排除眉毛，用脸宽椭圆近似脸缘，侧脸时自动降低强度。
2. 检测输入非等比拉伸：保留现有实现（已验证可用），在报告中标注精度限制；本轮不改检测模型。
3. 无 GPU：tract 纯 CPU；本轮保持 CPU 优先，接口层预留 `device` 字段，GPU 不可用时明确回退。
4. 蒙版显示、画笔、橡皮擦、反向、羽化、强度全部缺失，只有项目结构里的空 `masks: []`。
5. 一键美肤不存在；没有任何皮肤分析指标。
6. 预览请求不携带人脸版本；本轮用后端缓存 + 人脸版本号进入渲染缓存键。
7. `smooth_skin` 在基础分组，标签“磨皮”与实际能力不符；本轮迁入“皮肤质感”。

## 4. 本轮实施计划

1. **参数与状态**：`EditParams` 增加 `beauty`（磨皮/纹理/细节/祛痘/祛斑/黑头/肤色均匀/美白/泛红/暗沉/黑眼圈/眼下细纹/额头细纹/法令纹）、`faces[]`（按稳定 ID 的独立参数与开关）、`manualMask`（笔触、橡皮、羽化、强度、反向）；两端同步夹紧与中性判定。
2. **皮肤区域**：`ai_engine/skin_segmentation/`（几何蒙版、肤色似然、羽化、许可证闸门、模型状态、缓存）。
3. **自然磨皮**：引导滤波/域变换多尺度低频平滑 + 高频回注 + 蒙版融合，三档预设（轻/自然/强）。
4. **瑕疵修复**：局部残差检测 + 连通域筛选 + 环形采样修复 + 边缘融合；保守模式跳过痣与密集雀斑。
5. **肤色与眼周**：Lab 空间均匀/美白/泛红/暗沉；眼下与细纹按关键点椭圆蒙版，保护眼睛与睫毛。
6. **手动蒙版**：归一化笔触坐标，渲染时按实际分辨率重建；画笔/橡皮/显示/反转/羽化/强度/撤销笔触/恢复自动。
7. **多人脸**：ID 跟踪、按脸参数、独立开关、复制参数、重叠区域按最近脸归属。
8. **一键美肤**：检测 → 分割 → 指标分析（亮度/纹理/瑕疵密度/暗沉/泛红）→ 生成可编辑参数 → 预览 → 应用。
9. **前端**：AI 美肤、皮肤质感、瑕疵修复、肤色、眼周、人物分组；进度、错误、撤销入口；蒙版画布。
10. **测试**：蒙版包含/排除、纹理保留率、瑕疵对比度下降、肤色自然度指标、按脸独立性、撤销、导出、取消、耗时与内存。
11. **收尾**：构建、启动验证、`ROUND3_REPORT.md`、许可证表、提交。

## 5. 验收口径

- 眼睛/嘴唇/眉毛区域在蒙版内权重必须接近 0，测试用真实人像统计；
- 磨皮后高频能量保留比例写入测试输出，不得只凭主观描述；
- 瑕疵修复必须给出修复前后局部对比度数据；
- 按脸参数独立性用同一张多人照片的不同参数结果差异验证；
- 没有检测结果时，AI 美肤按钮必须报错或提示先检测，不能静默全图处理；
- 未授权分割权重不得打包，模型状态必须如实显示“未授权/不可用”。
