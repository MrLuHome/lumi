评估过的候选与结论记录在 [THIRD_PARTY_LICENSES.md](../THIRD_PARTY_LICENSES.md) 与审计文档：

- BiSeNet Face Parsing / CelebAMask-HQ 系权重：训练数据与模型卡限研究用途，仓库代码许可不能推断权重可商用；
- InsightFace 系解析权重：多数仅限非商业研究；
- MediaPipe Face Mesh：Apache-2.0，但 tflite→ONNX 权重再分发与 tract 算子兼容尚未完成法律与技术验证；
- MODNet 等抠图模型：只输出前景，不输出皮肤/五官分区，不满足需求。

这不是“暂用假数据”：`skin_segmentation/model.rs` 保留注册表、许可证白名单、SHA256 校验与拒绝加载逻辑；拿到书面商用授权后可直接登记加载。当前替代方案为可解释、可测试的几何蒙版，行为与限制如实写在下方。

## 4. 实际算法

### 4.1 皮肤区域（`landmark-geometry`）

1. 由 YuNet 5 点建立人脸坐标系：双眼中点为原点，双眼连线为 u 轴，垂直向下为 v 轴，眼距 `d` 为单位；v 轴方向按图像 y 向下修正。
2. 面部椭圆：半宽 `0.92d`、半高 `1.58d`，覆盖额头、双颊、鼻部、下巴；颈部候选区 `v∈[1.28,2.35]`，权重上限 `0.55`。
3. 五官保护椭圆（权重归零）：眼睛 `0.30×0.20`、眉毛（眼上 `v=-0.30`，`0.36×0.14`）、嘴 `0.44×0.24`、鼻孔 `0.17×0.12`。
4. YCbCr 肤色似然：中心 `Cb=0.402, Cr=0.600`，σ `0.125/0.095`；低亮度（`y<0.55`）按 `smoothstep` 最多放宽容差 1.3 倍，解决暗光/低对比肤色被压成中性而整片漏蒙版；高光低于 `y<0.085` 线性压低。
5. 高光裁切补偿：`y>0.93` 的裁切皮肤在**面部椭圆内**保留 ≤0.5 的几何置信度（纯白照片中不会把面部外背景算进来），避免过曝人像整张脸漏蒙版；由于裁切区没有可处理纹理，不会产生虚假细节。
6. 自动蒙版按 `0.02d` 羽化，`alpha<0.12` 归零；手动笔触按归一化坐标叠加/擦除，再按羽化参数柔化。
7. 多人脸用最近脸中心划分归属，重叠像素只归属一张脸。

限制：不是像素级解析，侧脸、重度遮挡、手/发丝挡脸时精度低于模型；眉毛位置由眼睛上方固定比例估计；这些情况在报告中如实标注，并有低置信度降权。

### 4.2 自然磨皮

- 自引导滤波两尺度：半径 `0.012×宽` 与 `2.2×`，`eps = 0.0015 + 0.045×(1-纹理保护)`；大尺度 `eps×1.8`，两者平均为基底。
- 高频回注：`keep = 0.08 + 0.45×纹理保护 + 0.22×细节恢复`（上限 0.95），`retention = min(1, keep + 0.35×细节恢复)`，`target = base + detail×retention`。
- 按蒙版 alpha × 强度融合；强度 0–100，三档预设：轻 22 / 自然 32 / 强 48（均为可继续编辑的参数）。
- 没有全局高斯；睫毛、唇线、痣等强边缘由引导滤波的局部方差保护。

### 4.3 祛痘祛斑

- 亮度残差：`box_mean(radius=1% 宽)` 为低频，残差低于阈值 `0.030+0.022×(1-强度/100)` 为候选。
- 约束：残差必须大于 `-0.22`（痣保护；黑头通道 `-0.30`）、亮度 `>0.08`、面积 `4..(4.5% 宽)²`、连通域长宽比 `≤3.2`、平均残差 `≤ -0.8×阈值`。
- 密集保护：自动模式下候选像素超过皮肤 1.2% 或组件数超过 40/120 时整体跳过，避免把雀斑、毛孔当痘痘。
- 修复：沿瑕疵外环采样皮肤色，按距离与边缘 0.65 混合，不做整片模糊；不同大小瑕疵用同一保守策略但受面积上限约束。
- 手动点选：`RepairPoint` 归一化坐标 + 半径，按质心过滤组件，只修点选范围内；前端逐个记录、可单独撤销、可再编辑。

### 4.4 肤色

Lab（D65）内处理：均匀化向局部 `a/b` 均值靠拢 0.55；泛红压低 `(a-12).max(0)×0.55`；暗沉仅作用于阴影 `(62-L).max(0)×0.28×shadow`；美白 `7×中间调`、`b-1.6`；色度限制在原值 `0.35–1.25` 倍，`L>96` 高光压缩。每项独立 0–100 强度。

### 4.5 黑眼圈与细纹

眼下椭圆（眼中心沿 v `+0.30`，半径 `0.34×0.20`）、眼周细纹带 `v∈[1.02,2.05]`、额头 `v∈[-1.15,-0.30]`、法令纹 `(±0.52,0.82)`；只在局部蒙版内平滑亮度，保留 50% 高频。睫毛、眉毛、眼球由五官保护椭圆排除，默认强度低（一键建议上限 45/25/20）。

### 4.6 多人脸与一键美肤

- `FaceTracker` 以 IoU≥0.25 贪心匹配上一轮结果，匹配不上才分配新 ID；`FaceRepository` 以路径缓存归一化人脸与版本，版本进入渲染缓存键。
- 参数按 `faceId` 存储（独立开关/强度/复制），检测顺序变化不会错配；重叠像素按最近脸中心归属。
- 一键美肤：逐脸统计蒙版覆盖率、平均亮度、高频纹理、瑕疵密度、色度变化、泛红、暗部/高光比例、眼下亮度差、眼周/额头/法令纹纹理，用确定性公式生成建议（磨皮 10–55、祛痘 0–55 等），侧脸/遮挡/密集小点/高光会降权并给出提示；产出是普通 `BeautyParams`，用户可见、可改、可撤销。

## 5. 性能与内存（release，Apple Silicon macOS）

| 场景 | 尺寸 | 结果 |
| --- | --- | --- |
| YuNet 检测（真实照片） | 1800px 预览 | 20–25 ms/张 |
| 皮肤蒙版（合成图基准） | 1600×1200，206,294 px | 15.2 ms |
| 单脸美肤（自然预设） | 1600×1200 | 82.7 ms |
| 完整管线 | 1600×1200 | 83.5 ms |
| 全分辨率美肤（真实人像） | 3360×4480 | 990 ms，RSS +265 MB（测试进程内，含原图/预览缓冲） |

- 人脸检测结果按图缓存，滑块变化与蒙版显示不会重跑 YuNet；渲染结果缓存 12 条、上限 160 MB，键包含图片路径、输出尺寸、人脸版本与完整参数。
- 所有命令在 `spawn_blocking` 中执行；渲染/导出使用 `CancelToken` 在阶段边界和逐行循环检查，新请求会取消旧请求。
- 导出始终用全尺寸缓冲；预览用 1800px 缩略。
- 本轮对引导滤波做了缓冲复用（用平方/平方均值数组存放 a/b），降低大图临时内存。

## 7. 已知问题

1. **分割权重授权阻塞**：没有可确认商用的皮肤解析权重，当前蒙版是几何方案，侧脸/遮挡精度低于模型；`skin_model_status` 如实返回 `available:false`。
2. **无 GPU 路径**：tract-onnx 纯 CPU，未接 ONNX Runtime / CoreML / Metal；GPU 加速未实现（CPU 始终可用，不存在“GPU 失败未回退”的问题）。
3. **大图未分块**：全分辨率一次性在内存中处理；3360×4480 峰值增加约 265 MB，超大图（>1 亿像素）有内存风险。
4. **蒙版未单独缓存**：每次渲染重建蒙版（1600×1200 约 15 ms）；人脸检测与最终预览有缓存，滑块变化不会重跑检测，但会重建蒙版与已启用的美肤节点。
5. **保守跳过原因未回传 UI**：自动祛痘在雀斑/强纹理图会跳过，引擎报告里有原因，当前渲染命令未把 `FaceRetouchReport` 返回前端，界面表现为“参数变了但无明显效果”。
6. **一键分析不可取消**：`analyze_beauty` 使用默认取消令牌，取消能力只覆盖渲染与导出。
7. **测试集缺口**：真实 fixture 覆盖正面、四人合照、高光、暗光、高分辨率；缺少侧脸、不同年龄、雀斑真人的样张，也没有人工标注的像素级蒙版真值，蒙版准确性用几何与保护区域断言衡量。测试照片来源授权仍待确认。
8. 编译仍有 2 个 dead_code 警告（`RenderRegistry::cancel_all`、`ImageCache::memory_usage`），不影响功能。
