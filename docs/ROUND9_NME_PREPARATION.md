# ROUND 9 准备：NME 评测方案（未执行，仅方案）

> 状态：**方案已就绪，评测尚未执行。**
> 在本文所述流程完成前，LUMI 不得宣称任何 Provider 的关键点「定位精度已验证」。

## 1. 目标与边界

- 目标：用人工标注真值衡量关键点定位误差，回答「点准不准」，而不是「重复跑是否一致」。
- 不在本轮范围：模型训练、微调、商业 SDK 集成。
- 适用对象：Apple Vision（`apple-vision`）、随包 YuNet（`yunet`）、用户 ONNX 模型（`onnx:*`）。
- 现有证据只覆盖：重复运行稳定性（`measure_stability`）与结构完整性（`evaluate_checks`）。
  **两者都不能替代 NME。**

## 2. 样本采集与授权

### 2.1 数量与构成

| 维度 | 最低要求 |
| --- | --- |
| 总样本 | ≥ 50 张，目标 80 张 |
| 人脸数 | ≥ 50 张单人正脸 + ≥ 10 张多脸/侧脸/遮挡 |
| 光照 | 顺光、逆光、弱光、硬光各 ≥ 8 张 |
| 肤色/年龄/性别 | 每类至少 5 张，避免单一分布 |
| 分辨率 | ≥ 1200×1600，含 2 张 4000px 以上 |
| 格式 | JPEG / PNG / HEIC 转换件；记录原始来源 |

### 2.2 采集方式

1. 自有拍摄或已获书面授权的图库样张。
2. 每张样本登记：`sample_id`、来源、作者、拍摄/下载日期、授权文件编号、允许用途（评测/内部）。
3. **禁止**使用来源不明、社交媒体抓取、含未授权第三方肖像的图片。
4. 涉及真人的样本需肖像使用授权；授权书扫描件单独归档，不进入仓库。

### 2.3 数据存放

```
evaluation/nme/
  manifest.json          # sample_id → 文件、授权编号、尺寸、人脸数
  images/                # 原始样本（不入 Git，单独加密归档）
  annotations/           # 人工标注 JSON（入 Git 前脱敏）
  licenses/              # 授权书编号索引（不存原件）
```

## 3. 关键点标注规范

- 坐标系：原图左上角为原点，归一化到 `0..1`，与 `face_intelligence::types` 一致。
- 拓扑：以 `face-68` 为主，Apple Vision 输出需映射到同一 68 点语义后再比较；
  映射表由 `ROUND8_TOPOLOGY.md` 固定，禁止评测时临时改映射。
- 标注工具输出：`{ "points": [[x, y], ...68], "regions": {...}, "occluded": [index...] }`。
- 规则：
  1. 每点由两名标注员独立标注，取平均；两点距离超过眼距 2% 时由第三人裁决。
  2. 不可见/被遮挡点标记 `occluded`，评测时单独统计，不计入主 NME。
  3. 不使用算法结果预填后再「微调」，避免把模型偏差写进真值。
  4. 标注完成后冻结版本号（`annotations-v1`），后续只增不改。

## 4. 评测脚本设计

建议新增 `src-tauri/tests/nme_eval.rs`（`#[ignore]`，手动运行）：

```text
输入：manifest.json + annotations/*.json + 指定 Provider
流程：
  1. 按 Provider 的 analyze() 获取稠密关键点；
  2. 按 face_uuid / 几何 IoU 与标注人脸一一匹配；
  3. 仅对非遮挡点计算欧氏距离；
  4. 按眼距归一化得到 NME；
  5. 输出总体与分区域统计。
输出：JSON + Markdown 表
```

### 4.1 指标

- **NME** = `mean(||pred_i - gt_i||) / inter_ocular_distance`，按脸归一化后再取全样本均值。
- **分区域 NME**：眼部（左右眼睑）、鼻部、唇部（内外唇）、下巴/脸缘分别统计。
- **P50 / P95**：逐点误差（归一化像素或按眼距归一化）的中位数与 95 分位。
- **失败率**：
  - 无人脸检出率；
  - 关键点缺失/非有限/越界率；
  - 分区缺失率（某区域点数不足）；
  - 稳定性失败率（复用 `measure_stability`）。
- **置信度校准**：检测级 `confidence` 与逐点误差的相关性；**不得**把检测级 confidence 当逐点 confidence。

### 4.2 通过门槛（建议，需架构师确认）

| 指标 | 建议门槛 |
| --- | --- |
| 总体 NME | ≤ 5%（正脸）；≤ 8%（侧脸/遮挡） |
| 眼部 NME | ≤ 4% |
| 鼻部 NME | ≤ 6% |
| 唇部 NME | ≤ 5% |
| P95 逐点误差 | ≤ 10% 眼距 |
| 失败率 | ≤ 5% |

未达门槛的 Provider 只能标记「稳定性/结构通过，精度未达标」，不得解锁商业宣传口径。

## 6. 风险与限制

- 50 张样本只够内部评测，不足以支撑「行业领先」类宣传。
- 标注误差本身会进入 NME；需报告标注员间一致性（建议 ICC 或平均点距）。
- Apple Vision 的 85 点需映射到 68 点，映射会引入额外误差，必须单独说明。
- 侧脸/大角度样本的 68 点语义本身有歧义，需在结果中分层报告。
