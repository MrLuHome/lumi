# ROUND 6.1 — 能力标注审计

目的：确保界面文案与实际算法一致，不把规则/几何方法描述成“AI 诊断”，未实现能力必须显式标注。

## 1. 审计范围

- `src/components/**`（BeautyPanel、SubjectMaskPanel、BodyPanel、ReshapePanel、SmartPanel、BatchWorkspace、CanvasStage）
- `src/lib/backend.ts` 的能力查询与兜底文案
- `src-tauri/src/commands/{beauty,segmentation,face_reshape,batch}.rs`
- `src-tauri/src/ai_engine/**`、`src-tauri/src/face_reshape/mod.rs` 的 `note` 字段

## 2. 结论

| 能力 | 实际实现 | 界面/返回值文案 | 结论 |
|---|---|---|---|
| 美肤精修 | 本地：人脸关键点 → 几何皮肤蒙版 → 频域/双边细节与色调调整 | “美肤精修”“自动皮肤分析”“皮肤分析完成” | 已去除“AI 美肤”表述（原 `AI 美肤`/`AI 美肤失败` 全部替换） |
| 智能精修建议 | 本地图像统计 + 规则（亮度/对比/高光/阴影/白平衡/肤色等 10 项） | “智能精修建议”“本地照片分析 · 不上传照片 · 建议可编辑可撤销”，历史记录标签“应用智能建议” | 与实现一致；建议逐项可编辑、可撤销 |
| 人物蒙版 | 用户手动画笔 + 本地 Alpha 处理 | “手动人物蒙版（非 AI 分割）”“AI 自动分割未启用。手动笔触是当前唯一可用的蒙版路径。” | 一致，未启用原因清晰 |
| 身材调整 | 手动蒙版轮廓 + 用户确认锚点 + 局部网格变形 | “不依赖 AI 姿态识别，不做整图拉伸” | 一致 |
| 人脸塑形 | LEVEL 1 手动变形 + LEVEL 2 轮廓级保守调整；LEVEL 3 未启用 | `note`: “LEVEL 3 稠密五官精修未启用”；关键点显示“稠密关键点（未启用）” | 一致 |
| 姿态识别 | 未启用（无授权权重、未验证） | “人体姿态模型未启用：没有可再分发的权重…” | 一致 |
| 人物分割 | 未启用（无授权权重） | “AI 人物分割未启用：仓库内没有经过再分发审查的权重…” | 一致 |
| 皮肤深度分析 | 未实现 | 界面不提供该入口，也没有“肤质诊断/皮肤年龄”类结果 | 不存在夸大表述 |

## 3. 本轮代码改动

- `src/components/BeautyPanel.tsx`：`AI 美肤` → `美肤精修`，`AI 美肤失败` → `美肤分析失败`。
- `src/lib/backend.ts`：`AI 美肤需要在桌面端运行` → `美肤分析需要在桌面端运行`。
- `src-tauri/src/commands/beauty.rs`：错误文案同步去掉“AI 美肤”。
- `src/state/editorStore.ts`：撤销/重做历史标签 `应用 AI 建议` → `应用智能建议`。

## 4. 未改动项（合理保留）

- 代码注释中的“AI 美肤面板”“非 AI 分割”等说明性文字，用于解释实现边界，不是用户可见能力宣称。
- `segmentation` / `pose` 的“未启用”文案保留，因为它们是**明确标注不可用**的能力说明。
