# ROUND 8 — 用户模型安全

- 代码：`face_intelligence/model_hub/security.rs`、`probe.rs`、`validator.rs`、`inference.rs`
- 原则：不执行用户模型中的代码；不因导入失败而崩溃；失败必须可解释、可追溯。

## 1. 威胁模型

| 威胁 | 具体形式 | 控制 |
|---|---|---|
| 伪装文件 | `.onnx` 实为 ZIP / NumPy / ELF / Mach-O / PDF / Git LFS 指针 | 读文件头签名，命中即拒 |
| 路径穿越 | 模型 ID 含 `../`、绝对路径、隐藏目录 | ID 白名单字符、长度 1..64、禁止 `.` 开头；`safe_join` 再次校验前缀 |
| 符号链接 | 指向任意位置的文件 | `symlink_metadata` 检测，拒绝符号链接 |
| 外部数据引用 | ONNX `external_data` 读取旁路文件 | 字节级扫描 `external_data`，拒绝 |
| 资源耗尽 | 超大文件、超大张量、死循环图 | 512 MB 体积上限；输入 32..1024 静态；子进程 20 s 超时 kill |
| 崩溃/panic | 恶意或损坏模型触发 tract panic | 校验与冒烟在独立子进程；`catch_unwind` 兜底 |
| 任意代码执行 | Python pickle、自定义算子、动态库 | 只接受 ONNX protobuf；不加载 `.py`、`.so`、`.dylib`；不执行模型内脚本 |
| 供应链替换 | 导入后文件被替换 | 每次使用/重验都核对 SHA256 |

## 2. 不做的处理（明确不承诺）

- 不做模型签名验证，也不声称模型“可信”；许可证状态固定为 `UserUnverified`。
- 不提供操作系统级沙盒（如 `sandbox-exec`/seccomp）；隔离只有独立子进程 + 超时 + 崩溃捕获。
- 不分析 ONNX 图中是否存在对抗性输入；模型可以输出错误的点，但不会获得代码执行权限。
- 不阻止模型使用大量内存；只有 512 MB 文件上限与 20 s 超时，操作系统仍可能因大张量换页。

## 3. 数据可追溯

manifest 保存：

- `sha256`、`fileSize`；
- `sourcePath`（导入时的原始绝对路径，仅用于追溯，不参与推理）；
- `sourceUrl`（可选，用户填写）；
- `importedAt`、`validation`（形状、算子数、耗时、警告、错误）；
- 许可证声明原文（`name/url/commercialUseClaimed/redistributionClaimed/note`），
  与派生的 `LicenseState::UserUnverified` 同时展示，避免把用户声明当成事实。

## 4. 失败语义

| 场景 | 用户看到 | 内部状态 |
|---|---|---|
| 扩展名不对 | “只接受 .onnx 模型，实际扩展名 `bin`” | 不写入模型目录 |
| 伪装 ZIP | “文件是 ZIP 压缩包，不是 ONNX 模型” | 不写入 |
| SHA256 与 manifest 不一致 | “模型文件已变化（SHA256 不匹配），请重新导入或重新验证” | 标记不可用，不自动降级到其他 Provider |
| 输入/输出契约不符 | “输出必须是 3 维……实际 4 维” | 该模型不注册 |
| 冒烟输出含 NaN/Inf | “输出包含 NaN/Inf（有限值比例 83.2%）” | 该模型不注册 |
| 探针超时 | “模型验证超过 20 秒，已终止” | 子进程被 kill，主进程继续 |

## 5. 已知缺口

1. **真实恶意模型样本未测试**：上述控制由单元测试覆盖文件头、路径、哈希；
   没有构造真实恶意 ONNX 图做过端到端攻击测试。
2. **异步超时与进程回收**只在代码层实现；未做“僵尸进程/高并发导入”的压力测试。
3. **Windows 未验证**：子进程模式在 Windows 下的行为（路径、终止信号）没有实机验证。
4. 512 MB 上限是经验值，未针对“合法但巨大”的 68 点模型做兼容性测试。
